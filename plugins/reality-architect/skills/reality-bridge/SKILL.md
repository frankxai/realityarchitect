# Build or check a Bridge

> **First:** read `CHARTER.md` at the root of this plugin if you have not read it in this session, and follow it.
> Non-negotiable: never promise an outcome or claim that thought or feeling causes one; never blame; ask before
> writing; keep desired, reported, planned, done and meaning apart; never design a move that depends on controlling
> another person's choices; health and money decisions go to qualified humans.

A Bridge is one aim, written as `STATE/aims/<slug>.md` (format: standard/STATE.md). It connects the person's
**desired** scene to what is **reported** true now, through **planned** acts.

## Find the home

`$REALITY_HOME/reality/` if set, else `~/.reality/` when `~/reality.md` exists, else offer `reality-onboard`. Never
write in the current working directory.

## Build (interview, one question at a time)

1. **Aim**, **done when** (something an outsider could verify) and **by** (a date).
2. **The scene (desired):** an ordinary moment when it is done, in the present tense.
3. **True now (reported):** one specific fact.
4. **Obstacle:** the first inner or outer obstacle, and its gap class: knowledge, capability, resource, coordination,
   technology, permission, process, evidence, or time. Then the if-then: "If <obstacle>, then I <act>." Pairing the
   scene with the obstacle and an if-then plan is the studied version of visualization.
5. **Skills to grow** (human) and **systems to build** (AI workflows), each tagged with its Architect's Loop move: See,
   Design, Build, Automate, Compound. Recommend only the first move they have not locked in.
6. **Reps:** recurring practice with a weekly count, small enough to keep.
7. **Bold moves:** one-off acts with dates. This is where "massive action" lives, made concrete.
8. **People and places:** roles to meet and environments to enter, each with why.

Planning is a conversation, not a commitment to storage. Show the complete aim file and ask: "Shall I save this to
`STATE/aims/<slug>.md`?" Write it **only after an explicit yes**. If the file exists, show the diff and keep their
earlier wording unless they change it.

## Check: "Is it enough?"

Window: the last 14 days, or since the bridge started. Overdue moves are not done and due **before** today; a move due
today is not overdue.

**With reps:** planned reps = sum of weekly counts × days ÷ 7; logged reps = `rep` entries for this aim in
`witness.md` within the window; ratio = logged ÷ planned.

| Condition | Answer |
| --- | --- |
| no reps and no moves | Not enough yet: nothing is defined to do. Add one rep for this week. |
| the date has passed | Review it: achieved, extend, or release. |
| started under 3 days ago, nothing logged | Too early to judge. Log the first rep. |
| ratio ≥ 0.8 and nothing overdue | On pace. |
| ratio ≥ 0.5 and at most one move overdue | Behind. Shrink the rep or move a date; do not add pressure. |
| otherwise | Not enough for the date. Make the rep smaller, change the environment, ask someone, or extend. |

**With moves only (no reps):** never divide by zero. All moves done → "Every planned move is done: is the done-when
true?" No move overdue → on pace. One overdue → behind. Two or more → not enough for the date.

Always show the numbers you used, and suggest **one** change: the smallest that would move the verdict.

## Never

- Never promise the aim will happen. Never call a slow week a character flaw.
