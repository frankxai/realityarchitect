# v0 on Reality Architect

v0 is a **visual compiler**, not the product. The product is a local `reality.md`, a checkable standard, and a waitlist Vault. This file is how agents may call [v0 MCP](https://v0.app/docs/api/v2/guides/mcp-server) against this repo.

## Two MCP directions (do not mix)

| Direction | URL / runtime | Job |
|---|---|---|
| **Agent → v0** | `https://v0.app/api/mcp` (OAuth, never an API key in MCP config) | Create/continue a chat, get a preview URL, iterate a **single route** |
| **v0 → our MCP** | HTTPS server we host later | Let v0 *generation* call `validate` / `brief` — not for site chrome |

Grok/Claude/Cursor connect **Agent → v0**. Users of the method connect **our** MCP (or the local CLI) so their contract never has to live in v0.

Do not put `V0_API_KEY` in MCP client config. First connect opens a browser; pick the Vercel team that owns `realityarchitect.ai`.

## When to call v0

Allowed: one screen or one component, when layout or type is the bottleneck.

Forbidden: generating `/api/waitlist`, `standard/`, `starter/`, checkout, auth, KV, or a second method. Forbidden: replacing `lib/site.ts` with v0 tokens. Forbidden: shipping a v0.app preview URL as the product.

## Sovereign stack we provide (not v0)

The Architect's Loop is the product. v0 is optional paint.

1. **See** — `~/reality.md` + `~/.reality/` (READ · SURFACE · PROPOSE · LOG · GUARD). CLI: `node standard/bin/reality-md.mjs validate|brief|emit`.
2. **Design** — one spec in `starter/`.
3. **Build** — named skills/agents in the user's repo; AGENTS.md they own.
4. **Automate** — local loops; optional later **eve** agent for waitlist mail, not for their life OS.
5. **Compound** — `~/.reality/evidence.md`.

**MCP we ship:** wrap the existing CLI as a local stdio server (`validate`, `brief`, `emit --target claude|codex|grok`). Data stays on their machine. Optional remote HTTPS only if they host it. Register that server **in v0** so generation can check a pasted (non-secret) sample — never upload a live `reality.md`.

**AI app:** the site is the assessment + brief exporter. The "app" is their agents reading their file. We do not host their memory.

**Plugins/skills:** MIT starters in `starter/`. Vault (waitlist) is filled contracts and loops with numbers — after gate PASS.
